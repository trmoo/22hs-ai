🤔 생각 열기

여러분에게 고양이 사진을 골라내는 프로그램을 만들라는 과제가 주어졌습니다. 조건은 하나 — if 문으로만 만들어야 합니다.

  • “귀가 삼각형이면 고양이”라고 썼습니다. 그런데 접힌 귀 고양이가 나왔습니다.
  • “수염이 있으면 고양이”라고 고쳤습니다. 그런데 수염이 안 보이게 찍힌 사진이 나왔습니다.
  • “털이 있고 눈이 두 개면 고양이”라고 했습니다. 그런데 강아지가 걸렸습니다.

규칙을 100개, 1000개 써도 다음 사진은 또 예외입니다. 그런데 여섯 살 아이는 고양이 사진 몇 장만 보고도 처음 보는 고양이를 알아맞힙니다. 아이는 규칙을 배운 것이 아니라 예시를 본 것입니다.

힌트 그렇다면 컴퓨터에게도 “예시”를 보여 주면 어떨까?
이 차시는 바로 그 발상의 전환을 다룹니다. 사람이 규칙을 쓰는 대신, 컴퓨터에게 데이터와 정답을 주고 규칙을 스스로 찾아내게 하는 방법 — 그것이 기계학습입니다.
1

규칙을 쓰는 프로그래밍, 규칙을 찾는 프로그래밍

1단원에서 배운 탐색과 추론은 모두 사람이 규칙을 미리 정해 주는 방식이었습니다. 미로의 이동 규칙, 추론 엔진의 IF-THEN 규칙 — 컴퓨터는 사람이 준 규칙을 빠르고 정확하게 실행했을 뿐입니다. 이것을 전통적 프로그래밍이라고 부릅니다.

전통적 프로그래밍에서는 규칙과 데이터를 넣으면 답이 나옵니다. 그런데 기계학습은 이 화살표를 뒤집습니다. 데이터와 답을 넣으면 규칙이 나옵니다. 이 한 문장이 기계학습의 전부라고 해도 지나치지 않습니다.

📘 개념

기계학습은 사람이 규칙을 직접 작성하지 않고, 데이터와 정답의 관계를 컴퓨터가 스스로 찾아내도록 하는 방법이다. 학습의 결과로 만들어진 규칙 덩어리를 모델이라고 한다.

기계학습이라는 말은 1959년 아서 새뮤얼이 “명시적으로 프로그래밍하지 않고도 컴퓨터가 학습하게 하는 연구 분야”라고 설명하면서 널리 쓰이게 되었습니다. 여기서 중요한 것은 “명시적으로 프로그래밍하지 않고도”라는 부분입니다. 프로그래머가 if 스팸단어 in 메일: 같은 문장을 쓰지 않는다는 뜻입니다.

두 방식의 비교 — 무엇을 사람이 하고 무엇을 컴퓨터가 하는가
구분전통적 프로그래밍기계학습
사람이 하는 일규칙(알고리즘)을 직접 작성데이터를 모으고 정답을 붙이고, 학습 방법을 고름
컴퓨터가 하는 일규칙을 그대로 실행데이터에서 규칙(모델)을 찾아냄
입력 → 출력규칙 + 데이터 → 답데이터 + 답 → 규칙
새로운 예외사람이 규칙을 추가해야 함데이터를 더 주면 스스로 반영
잘 맞는 문제세금 계산, 성적 산출, 신호 제어얼굴 인식, 번역, 추천, 이상 거래 탐지
결과 설명규칙을 읽으면 이유를 알 수 있음왜 그렇게 판단했는지 설명이 어려울 수 있음
⚠️ 오해 주의

기계학습이 전통적 프로그래밍보다 언제나 더 좋은 것은 아닙니다. 부가가치세를 계산하는 프로그램에 기계학습을 쓰면 어리석은 일입니다. 규칙이 이미 정확하게 정해져 있는 문제는 그 규칙을 그대로 코드로 쓰는 것이 더 빠르고 정확하며, 틀렸을 때 고치기도 쉽습니다.

2

무엇을 보고, 무엇을 맞히는가

기계학습을 하려면 먼저 데이터를 두 부분으로 나누어 생각해야 합니다. 무엇을 보고 판단할지와 무엇을 맞혀야 하는지입니다.

🔎

특성 (feature)

판단의 근거로 삼는 값입니다. 특성은 모델의 입력이 되며, 통계에서 말하는 독립변수에 해당합니다. 예를 들어 집값을 예측할 때 면적·방 개수·지하철 거리가 특성입니다.

🎯

레이블 (label)

맞혀야 하는 정답입니다. 레이블은 모델의 출력이 되며, 통계의 종속변수에 해당합니다. 집값 예측에서는 실제 거래 가격이 레이블입니다.

같은 개념을 부르는 여러 이름 — 책이나 도구마다 표현이 다르므로 함께 알아 두면 좋다
역할기계학습 용어통계 용어표에서의 위치
입력(근거)특성, 속성, 입력 변수독립변수, 설명변수정답을 뺀 나머지 열
출력(정답)레이블, 목표값, 타깃종속변수, 반응변수맞히려는 그 한 열
한 건의 자료샘플, 데이터 하나관측값, 개체표의 한 행

학습은 두 단계로 나뉜다

기계학습 프로그램은 항상 두 단계를 거칩니다. 이 두 단계를 구분하지 못하면 이후 차시의 내용이 뒤엉키므로 확실히 잡아 둡시다.

  1. 훈련 단계 — 특성과 레이블이 함께 있는 데이터를 모델에 보여 주며, 예측이 정답에 가까워지도록 모델 내부의 값을 조금씩 고칩니다. 시간과 계산량이 많이 듭니다.
  2. 추론 단계 — 훈련이 끝난 모델에 레이블이 없는 새 데이터를 넣어 답을 얻습니다. 보통 매우 빠릅니다.
🔍 왜 두 단계를 나누어야 할까?

훈련에 쓴 데이터로 성능을 재면 실력을 부풀려 재게 됩니다. 시험 문제를 미리 알려 주고 시험을 보는 것과 같습니다. 그래서 데이터를 훈련 데이터와 테스트 데이터로 나누고, 성능은 반드시 한 번도 학습에 쓰지 않은 테스트 데이터로 잽니다. 아래 시뮬레이터에서도 훈련 메일 20통과 테스트 메일 10통을 철저히 분리해 둡니다. 이 이야기는 6차시에서 자세히 다룹니다.

3

기계학습의 세 갈래

기계학습은 학습에 쓰는 신호가 무엇인가에 따라 크게 세 유형으로 나뉩니다. 구분하는 방법은 뜻밖에 간단합니다. 정답이 주어졌는가? 그리고 보상이 있는가? 이 두 질문만 던지면 됩니다.

🧑‍🏫

지도학습

지도학습은 정답이 붙은 데이터로 배웁니다. 결과가 범주면 분류, 결과가 연속된 수면 회귀입니다.

🧩

비지도학습

비지도학습은 정답이 없는 데이터에서 숨은 구조를 찾습니다. 비슷한 것끼리 묶는 군집과, 속성 개수를 줄이는 차원 축소가 대표적입니다.

🕹️

강화학습

강화학습은 정답 대신 행동의 결과로 받는 보상을 씁니다. 보상의 합을 가장 크게 만드는 행동 방식을 시행착오로 익힙니다.

분류와 군집은 다릅니다. 둘 다 “묶는” 일처럼 보이지만, 분류는 이미 정해진 칸에 넣는 일(지도학습)이고 군집은 칸 자체를 데이터에서 만들어 내는 일(비지도학습)입니다. “스팸/정상으로 나눈다”는 분류이고, “고객들이 몇 개 무리로 나뉘는지 알아본다”는 군집입니다.

회귀는 “되돌아간다”는 뜻이 아닙니다. 통계 용어에서 유래한 이름일 뿐, 실제로는 연속된 수를 예측하는 일을 가리킵니다.

4

기계학습을 쓸 문제 고르기

성취기준 12인기02-01은 “기계학습을 적용할 문제를 정의하고, 문제 해결에 필요한 데이터를 선정하여 수집한다”입니다. 문제를 정의한다는 것은 곧 이 문제에 기계학습이 맞는지 판단한다는 뜻입니다. 다음 세 가지를 순서대로 따져 보면 됩니다.

  1. 규칙이 명확한가? 규칙을 몇 줄로 정확히 쓸 수 있다면 그냥 코드로 쓰는 편이 낫습니다. 반대로 “어떻게 알아보는지 나도 설명은 못 하겠는데 보면 안다”면 기계학습의 자리입니다.
  2. 데이터가 충분히 있는가? 기계학습은 예시로 배웁니다. 예시가 열 건뿐이라면 배울 것이 없습니다. 특히 정답이 붙은 데이터를 모을 수 있는지가 관건입니다.
  3. 예외가 많고 계속 변하는가? 예외가 끝없이 생기는 문제일수록 규칙을 손으로 관리하기 어렵습니다. 데이터를 다시 모아 학습을 되풀이하는 편이 유리합니다.
판단 연습 — 같은 분야에도 알맞은 문제와 알맞지 않은 문제가 섞여 있다
문제알맞은 방식이유
주민등록번호가 올바른 형식인지 검사전통적 프로그래밍검사 규칙이 법으로 정확히 정해져 있다
손으로 쓴 우편번호 읽기기계학습글씨 모양이 사람마다 달라 규칙으로 쓸 수 없다
도서관 대출 기한 계산전통적 프로그래밍규정을 그대로 코드로 옮기면 된다
학교 급식 잔반량 예측기계학습메뉴·날씨·요일 등 여러 요인이 복잡하게 얽혀 있다
새로 생긴 병의 진단 (환자 자료 12건)둘 다 어렵다데이터가 너무 적어 학습이 불가능하다
✅ 정리

기계학습은 규칙을 말로 쓰기 어렵고, 예시 데이터는 많고, 예외가 계속 생기는 문제에서 빛을 냅니다. 세 조건 중 하나라도 크게 어긋나면 다른 방법을 먼저 생각해 보아야 합니다.

데이터가 곧 규칙이다 — 그래서 위험하다

기계학습에서 규칙은 데이터에서 나옵니다. 그러므로 데이터가 한쪽으로 치우쳐 있으면 모델도 똑같이 치우칩니다. 채용 지원서 데이터에 특정 대학 출신이 압도적으로 많았다면, 모델은 “그 대학이면 합격”이라는 규칙을 배워 버립니다. 사람이 그런 규칙을 쓴 적이 없는데도 말입니다.

더 곤란한 점은 이 규칙이 코드에 적혀 있지 않아서 눈에 잘 띄지 않는다는 것입니다. 데이터가 어떻게 모였는지 따져 보지 않으면 알아채기 어렵습니다. 이 문제는 2차시(데이터 다듬기)에서 기술적으로, 3단원(인공지능의 사회적 영향)에서 윤리적으로 다시 다룹니다.

심화 세 유형 사이의 회색 지대 — 준지도학습과 자기지도학습

현실에서는 “정답이 있다/없다”가 딱 나뉘지 않습니다.

  • 준지도학습 — 정답이 붙은 데이터는 조금(예: 1000장), 정답이 없는 데이터는 아주 많을 때(예: 100만 장) 둘을 함께 씁니다. 정답을 붙이는 데 사람의 시간과 비용이 많이 들기 때문에 실무에서 매우 흔합니다.
  • 자기지도학습 — 데이터 자체에서 정답을 만들어 냅니다. 문장의 한 단어를 가리고 그 단어를 맞히게 하면, 사람이 정답을 붙이지 않았어도 정답이 있는 문제가 됩니다. 오늘날 거대 언어 모델이 바로 이 방법으로 학습합니다.

그래도 처음 배울 때는 정답이 있는가 / 보상이 있는가라는 두 질문으로 세 유형을 구분하는 연습이 가장 도움이 됩니다.

코드 훈련과 추론이 코드에서는 어떻게 나뉘는가

파이썬의 사이킷런(scikit-learn)에서는 훈련과 추론이 딱 두 줄로 나뉩니다. 어떤 알고리즘을 쓰든 이 모양은 그대로입니다.

from sklearn.naive_bayes import MultinomialNB

model = MultinomialNB()

model.fit(X_train, y_train)      # ← 훈련: 특성 X 와 레이블 y 를 함께 준다
pred  = model.predict(X_test)    # ← 추론: 특성만 준다 (레이블은 주지 않는다)

fit에는 y(레이블)가 들어가지만 predict에는 들어가지 않습니다. 이 차이가 곧 훈련과 추론의 차이입니다. 비지도학습에서는 fit(X)처럼 y 없이 호출한다는 점도 눈여겨보세요.
