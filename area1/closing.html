🤔 돌아보며 열기

1단원에서 우리는 다섯 차시 동안 서로 달라 보이는 것들을 배웠습니다. 튜링 테스트, 물병 퍼즐, 미로, 별표가 붙은 이상한 이름의 알고리즘, 그리고 규칙과 사실.

그런데 이 다섯 가지는 사실 하나의 질문에 대한 답입니다. 그 질문은 이것입니다.

“기계는 어떻게 답을 찾아내는가?”

지금 책을 덮고, 이 질문에 여러분의 말로 3문장 안에 답해 보세요. 잘 안 된다면 이 마무리 페이지가 꼭 필요한 사람입니다.

힌트 답의 뼈대는 두 갈래입니다
기계가 답을 찾는 길은 크게 두 갈래입니다. 하나는 가능한 상황을 늘어놓고 길을 찾아가는 것(탐색)이고, 다른 하나는 이미 아는 것에서 새로운 사실을 끌어내는 것(추론)입니다. 2·3·4차시가 앞의 길, 5차시가 뒤의 길이었습니다.
1

한 장으로 보는 1단원 개념 지도

1~5차시

아래 지도에서 상자는 개념, 화살표는 “이것이 저것으로 이어진다”는 관계입니다. 상자 왼쪽 위의 작은 표시는 그 개념을 배운 차시입니다.

🧭 지도를 읽는 세 가지 방법
  • 위에서 아래로 — 막연한 문제가 상태 공간이 되고, 상태 공간이 알고리즘이 되고, 알고리즘이 답이 됩니다.
  • 왼쪽과 오른쪽을 비교 — 왼쪽(탐색)은 가능한 경우를 훑어 답을 찾고, 오른쪽(추론)은 이미 아는 것을 조합해 답을 만듭니다. 같은 문제도 어느 길로 갈지 선택할 수 있습니다.
  • 맨 아래 줄에서 위로 — 맹목적 탐색 → 최상 우선 → A* 로 오면서 “쓰는 정보의 양”이 늘어나고, 그만큼 확인해야 하는 상태 수가 줄어듭니다.
2

차시별 핵심 정리

표의 마지막 열은 시험과 수행평가에서 가장 많이 틀리는 지점입니다. 이 열만 따로 읽어도 좋습니다.

1단원 인공지능의 이해 — 차시별 정리
차시꼭 알아야 할 개념한 줄 요약자주 나오는 오해
1차시
기계도 생각할 수 있을까		 지능적 판단, 튜링 테스트, 인공지능 활용 사례 인공지능은 사람의 지능적인 행동을 모방하여 상황에 맞는 판단을 내리는 기술이다. “튜링 테스트를 통과하면 기계가 사람처럼 생각한다” → 튜링 테스트는 겉으로 드러난 대화만 판정합니다. 속으로 이해했는지는 묻지 않습니다.
2차시
모든 문제는 탐색이 된다		 상태, 상태 공간, 초기 상태, 목표 상태, 연산자, 탐색 트리 문제를 상태 공간으로 바꾸면 “답 찾기”가 “초기 상태에서 목표 상태까지 길 찾기”가 된다. “상태 공간은 그림으로 다 그릴 수 있다” → 상태 수는 보통 기하급수적으로 늘어납니다. 그림은 일부만 그린 것이고, 그래서 탐색 순서가 중요해집니다.
3차시
무작정 뒤지기		 맹목적 탐색, 프런티어, 너비 우선 탐색(큐), 깊이 우선 탐색(스택) 두 알고리즘의 뼈대는 같고, 프런티어에서 무엇을 먼저 꺼내는지만 다르다. “깊이 우선 탐색이 빠르니까 더 좋다” → 확인한 칸이 적은 것과 짧은 길을 찾은 것은 다릅니다. 최단 경로를 보장하는 쪽은 너비 우선 탐색입니다.
4차시
눈치껏 찾아가기		 정보 이용 탐색, 휴리스틱, 최상 우선 탐색, A* 탐색, f = g + h 남은 거리 추정값 h 를 쓰면 목표 쪽으로 먼저 뻗어 나가고, 지금까지 온 비용 g 까지 더하면 최단 경로까지 지킬 수 있다. “A* 는 항상 최단 경로를 찾는다” → 휴리스틱이 실제 남은 비용을 넘겨 어림잡지 않을 때만 최적을 보장합니다. 또 최상 우선 탐색은 h 만 보므로 최적이 아닙니다.
5차시
아는 것에서 새것을		 지식 표현, 명제, 규칙(IF-THEN), 사실, 지식 베이스, 전방 추론 사실에 적용할 수 있는 규칙을 반복해서 적용하면, 아무도 직접 넣어 주지 않은 새로운 지식이 생긴다. “추론은 데이터를 학습하는 것이다” → 이 차시의 추론은 사람이 넣은 규칙을 적용하는 것입니다. 데이터로 규칙을 스스로 찾아내는 것은 2단원의 기계학습입니다.
🎯

탐색 3종을 한 줄로

너비 우선은 “가까운 데부터 전부”, 깊이 우선은 “한 방향으로 끝까지”, A*는 “여기까지 온 값 + 남은 어림값이 가장 작은 것부터”입니다.

⚖️

g 와 h 의 역할

g는 과거(출발점부터 지금까지 실제로 쓴 비용), h는 미래(목표까지 남았을 것으로 어림잡은 비용)입니다. 과거만 보면 너비 우선, 미래만 보면 최상 우선, 둘을 더하면 A* 입니다.

🧱

탐색과 추론의 공통점

둘 다 기호로 표현된 지식을 다룹니다. 상태와 연산자, 사실과 규칙 모두 사람이 정해서 넣어 준 형식입니다. 그래서 1단원을 기호주의 인공지능이라고 부릅니다.

핵심 용어 빈칸 점검

본문 빈칸 13개

아래 네 문단은 1단원 전체를 압축한 요약입니다. 위쪽의 빈칸 채우기 모드를 켜고 직접 채워 보세요. 힌트 버튼(?)을 눌러도 좋지만, 먼저 문장 흐름으로 유추해 보는 편이 훨씬 오래 남습니다.

① 지능적 판단이란 무엇인가

인공지능은 사람의 지능적인 행동을 모방해 상황에 맞는 판단을 내립니다. 기계가 지능을 가졌는지 겉으로 판정해 보려는 고전적인 실험이 앨런 튜링이 제안한 튜링 테스트입니다. 이 실험은 기계의 속마음을 들여다보지 않고, 사람과 구별되지 않는 행동을 보이는지만 따집니다.

② 문제를 탐색으로 바꾸기

인공지능이 문제를 풀려면 먼저 문제를 다룰 수 있는 형태로 바꿔야 합니다. 문제에서 나타날 수 있는 모든 상황을 상태로 보고, 그 상태들과 상태 사이의 연결을 모두 모은 것을 상태 공간이라고 합니다. 이렇게 바꾸면 문제 풀이는 초기 상태에서 출발해 목표 상태에 이르는 길을 찾는 일이 됩니다. 이때 한 상태를 다른 상태로 바꾸는 규칙을 연산자라고 부릅니다.

③ 어떤 순서로 뒤질 것인가

목표가 어느 쪽에 있는지에 대한 정보를 전혀 쓰지 않고 상태 공간을 기계적으로 훑는 방식을 맹목적 탐색이라고 합니다. 아직 확인하지 않은 후보 상태들의 목록인 프런티어를 큐로 쓰면 시작점에서 가까운 순서대로 퍼져 나가는 너비 우선 탐색이 되고, 스택으로 쓰면 한 방향으로 끝까지 파고드는 깊이 우선 탐색이 됩니다. 가중치가 없는 그래프에서 너비 우선 탐색은 최단 경로를 보장하지만, 같은 깊이의 상태를 모두 담아야 해서 기억 공간을 많이 씁니다.

목표까지 남은 비용을 어림잡은 값을 휴리스틱이라고 합니다. 이 추정값 h 만 보고 가장 그럴듯한 상태를 먼저 꺼내는 알고리즘이 최상 우선 탐색이고, 여기에 지금까지 실제로 쓴 비용 g 를 더해 f = g + h 로 판단하는 알고리즘이 A* 탐색입니다.

④ 아는 것에서 새로운 것을 끌어내기

탐색이 아닌 다른 길도 있습니다. 사람이 아는 것을 IF-THEN 형태의 규칙과 참으로 인정된 사실로 적어 두면, 그 둘을 모아 둔 지식 베이스가 만들어집니다. 여기서 사실에 적용할 수 있는 규칙을 찾아 결론을 새 사실로 추가하고 이 과정을 반복하는 방식을 전방 추론이라고 합니다. 반대로 알고 싶은 결론에서 거꾸로 필요한 조건을 찾아 내려가는 방식은 후방 추론입니다.

⚠️ 여기서 헷갈리면 반드시 다시 보기

연산자와 규칙은 다른 개념입니다. 연산자는 상태를 다른 상태로 바꾸는 행동(2차시)이고, 규칙은 사실에서 새 사실을 만드는 논리 문장(5차시)입니다. 둘 다 “IF … THEN …” 처럼 보일 수 있지만, 하나는 이동, 하나는 결론입니다.

서·논술형 문항

정답이 하나가 아닌 문항입니다. 각 문항 아래의 평가 기준을 먼저 펼쳐 보고, 그 요소들이 내 글에 들어 있는지 확인하며 쓰세요.

문항 1 · 서술형

같은 미로에서 너비 우선 탐색, 최상 우선 탐색, A* 탐색을 실행하면 확인한 칸 수와 찾아낸 경로 길이가 서로 달라집니다. 세 알고리즘이 프런티어에서 다음 상태를 고르는 기준을 각각 밝히고, 그 기준 때문에 결과가 어떻게 달라지는지 설명하시오.

평가 기준 좋은 답에 반드시 들어가야 할 요소
  • 세 알고리즘의 선택 기준을 각각 정확히 언급했는가 — 너비 우선은 가장 먼저 넣은 것(g 순서에 해당), 최상 우선은 h 가 가장 작은 것, A* 는 f = g + h 가 가장 작은 것.
  • g 와 h 가 각각 지금까지의 비용과 남은 비용의 추정임을 구분해 썼는가.
  • 결과의 차이를 확인한 칸 수(효율)와 경로 길이(최적성) 두 축으로 나누어 설명했는가.
  • 최상 우선 탐색이 빠를 수 있지만 최단 경로를 보장하지 않는 이유를 g 를 무시한다는 점과 연결했는가.
  • 시뮬레이터에서 관찰한 구체적인 숫자를 근거로 제시했는가.
문항 2 · 논술형

주변에서 문제 상황 두 가지를 고르시오. 하나는 탐색으로 푸는 것이 적절한 문제, 다른 하나는 규칙 기반 추론으로 푸는 것이 적절한 문제여야 합니다. 각각을 고른 이유를 이 단원에서 배운 개념으로 설명하시오.

평가 기준 좋은 답에 반드시 들어가야 할 요소
  • 두 문제 상황이 구체적인가(“교통”이 아니라 “학교 앞 등교 시간 최단 경로” 수준).
  • 탐색 쪽 문제에서 상태·연산자·목표 상태가 무엇인지 밝혔는가.
  • 추론 쪽 문제에서 사실과 규칙의 예를 한 개 이상 IF-THEN 형태로 썼는가.
  • 왜 반대로 하면 어려운지를 설명했는가(예: 상태 수가 너무 많아 탐색이 비효율적, 또는 규칙으로 적기 어려운 예외가 너무 많음).
  • 두 방법 모두 사람이 지식을 기호로 넣어 준다는 공통 한계를 언급하면 더 좋습니다.
문항 3 · 설계형

우리 학교나 우리 지역의 문제 하나를 골라 상태 공간으로 정의하고, 그 문제에 쓸 수 있는 휴리스틱을 직접 제안하시오. 제안한 휴리스틱이 왜 타당한지도 함께 밝히시오.

평가 기준 좋은 답에 반드시 들어가야 할 요소
  • 상태를 무엇으로 표현할지 정했는가(예: 방문한 교실의 집합과 현재 위치).
  • 초기 상태 · 목표 상태 · 연산자를 빠짐없이 적었는가.
  • 제안한 휴리스틱이 계산하기 쉬운가, 그리고 실제 남은 비용을 넘겨 어림잡지 않는가를 따졌는가.
  • 이 휴리스틱을 쓰면 맹목적 탐색보다 어떤 점이 나아지는지 예상했는가.
  • 휴리스틱이 잘못될 수 있는 상황(반례)을 하나라도 떠올렸다면 매우 우수한 답입니다.

심화 왜 A* 는 이름에 별표가 붙었을까

1968년 닐슨, 하트, 라파엘이 제안한 이 알고리즘의 이름은 원래 “알고리즘 A”였습니다. 뒤에 휴리스틱이 실제 남은 비용을 넘겨 어림잡지 않는다는 조건을 만족할 때 최적 경로를 반드시 찾는다는 것이 증명되었고, 그 최적성을 갖춘 판을 구별하려고 별표를 붙여 A* 라고 불렀습니다.

여기서 중요한 것은 이름이 아니라 조건입니다. 휴리스틱을 잘못 만들면 A* 라도 최단 경로를 놓칩니다. 예를 들어 격자 미로에서 상하좌우로만 움직일 수 있는데 직선거리를 두 배로 부풀려 h 를 쓰면, 실제보다 크게 어림잡은 셈이라 최적성이 깨집니다.

코드 세 알고리즘을 한 함수로 쓰기

시뮬레이터가 실제로 하는 일을 파이썬으로 옮기면 이렇게 됩니다. 꺼내는 기준(key)만 바꾸면 세 알고리즘이 모두 나옵니다.

def search(start, goal, neighbors, h, mode):
    frontier = [(start, 0)]          # (상태, 지금까지 비용 g)
    visited = set()
    while frontier:
        if mode == 'bfs':
            node, g = frontier.pop(0)                        # 가장 먼저 넣은 것
        elif mode == 'dfs':
            node, g = frontier.pop()                         # 가장 나중에 넣은 것
        elif mode == 'best':
            i = min(range(len(frontier)), key=lambda k: h(frontier[k][0]))
            node, g = frontier.pop(i)                        # h 가 가장 작은 것
        else:  # 'astar'
            i = min(range(len(frontier)), key=lambda k: frontier[k][1] + h(frontier[k][0]))
            node, g = frontier.pop(i)                        # f = g + h 가 가장 작은 것
        if node in visited:
            continue
        visited.add(node)
        if node == goal:
            return len(visited), g
        for nb in neighbors(node):
            frontier.append((nb, g + 1))

실제 A* 는 이 min 대신 우선순위 큐(파이썬의 heapq)를 써서 훨씬 빠르게 꺼냅니다. 알고리즘의 뜻은 같고 자료구조만 다릅니다.

사례 이 단원의 개념이 실제로 쓰이는 곳
  • 내비게이션 길찾기 — 도로망을 상태 공간으로 보고 A* 계열 알고리즘을 씁니다. 휴리스틱은 목적지까지의 직선거리를 제한 속도로 나눈 최소 예상 시간입니다.
  • 게임 속 캐릭터 이동 — 격자 지도에서 A* 로 경로를 찾고, 장애물이 바뀌면 다시 계산합니다.
  • 물류 창고 로봇 — 여러 로봇이 부딪히지 않도록 상태에 “시간”까지 넣어 탐색합니다. 상태 공간이 훨씬 커지므로 휴리스틱이 더 중요해집니다.
  • 의료 진단 지원 규칙 시스템 — 증상을 사실로, 진단 지침을 규칙으로 넣어 전방 추론으로 후보를 좁힙니다. 근거를 사람이 확인할 수 있다는 점이 강점입니다.
