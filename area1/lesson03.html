  • 가온은 갈림길마다 “일단 가까운 데부터 전부 확인”하며 한 칸씩 넓게 퍼져 나갑니다.
  • 나리는 “한 방향으로 끝까지 가 보고, 막히면 되돌아온다”를 반복합니다.

두 사람 모두 결국 출구를 찾긴 합니다. 그런데 누가 더 짧은 길로 나올까요? 그리고 누가 더 적은 칸을 확인할까요?

가온은 넓게(폭 우선), 나리는 깊게(깊이 우선) 탐색합니다. 이 차시에서 두 방식을 나란히 돌려 보며 무엇이 다른지 눈으로 확인합니다.
1

목표가 어딘지 모른 채 뒤지기

지난 차시에서 문제를 상태 공간으로 바꾸면 “답 찾기”가 “길 찾기”가 된다는 것을 배웠습니다. 그렇다면 그 넓은 상태 공간을 어떤 순서로 뒤져야 할까요?

가장 단순한 방법은 맹목적 탐색입니다. 이름 그대로 목표가 어느 쪽에 있는지에 대한 정보를 전혀 쓰지 않고, 정해진 순서대로 상태를 하나씩 확인합니다. 무정보 탐색이라고도 부릅니다.

📘 개념

맹목적 탐색은 목표까지 얼마나 남았는지 추정하지 않고, 상태 공간을 기계적으로 훑는 탐색이다. 언젠가는 답을 찾지만(완전성), 상태 공간이 커지면 확인해야 할 상태 수가 폭발적으로 늘어난다.

맹목적 탐색의 두 대표 선수가 너비 우선 탐색과 깊이 우선 탐색입니다. 놀랍게도 이 둘의 알고리즘은 딱 한 군데만 다릅니다.

두 탐색의 공통 뼈대

둘 다 “아직 확인하지 않았지만 곧 확인할 후보” 목록을 들고 다닙니다. 이 목록을 프런티어라고 부릅니다. 알고리즘은 이 과정을 반복합니다.

  1. 프런티어에서 상태 하나를 꺼낸다.
  2. 이미 확인한 상태면 버리고, 아니면 방문 표시를 한다.
  3. 그 상태가 목표면 끝. 아니면 이웃 상태들을 프런티어에 넣는다.
⚠️ 딱 한 가지 차이

1번에서 어느 것을 꺼내는가만 다릅니다. 너비 우선은 가장 먼저 넣은 것을 꺼내고, 깊이 우선은 가장 나중에 넣은 것을 꺼냅니다.

너비 우선 탐색 (BFS)

프런티어를 큐로 씁니다. 먼저 들어간 상태가 먼저 나오는 선입선출이라, 시작점에서 가까운 순서대로 퍼져 나갑니다. 가중치가 없는 그래프에서는 최단 경로를 보장합니다.

📚

깊이 우선 탐색 (DFS)

프런티어를 스택으로 씁니다. 나중에 들어간 상태가 먼저 나오는 후입선출이라, 한 방향으로 끝까지 파고들다 막히면 되돌아옵니다(백트래킹).

🔍 왜 BFS가 최단 경로를 보장할까?

큐는 시작점에서 1칸 거리인 상태 전부 → 2칸 거리인 상태 전부 → 3칸 … 순서로 꺼냅니다. 그래서 목표를 처음 꺼내는 순간이 곧 가장 짧은 거리일 때입니다. 반대로 스택은 깊이 순서를 지키지 않으니, 먼저 도착한 길이 최단이라는 보장이 없습니다.

심화 깊이 제한 탐색과 반복적 깊이 증가 탐색

DFS는 메모리를 아끼지만 깊은 갈래에 빠지면 돌아오지 못할 수 있습니다. 그래서 깊이를 L로 제한하는 깊이 제한 탐색을 씁니다. 하지만 L을 잘못 잡으면 목표를 놓치죠.

반복적 깊이 증가 탐색(IDDFS)은 L=1, 2, 3… 으로 늘려 가며 DFS를 반복합니다. DFS의 적은 메모리와 BFS의 최단 경로 보장을 함께 얻습니다. 같은 곳을 여러 번 방문하지만, 마지막 층이 전체 노드의 대부분이라 낭비가 생각보다 작습니다.

코드 파이썬으로 쓴 두 탐색 — 한 줄만 다르다

아래 두 함수를 비교해 보세요. 딱 한 줄만 다릅니다.

너비 우선 탐색깊이 우선 탐색
 
def bfs(start, goal, neighbors):
    frontier = [start]
    visited = set()
    while frontier:
        node = frontier.pop(0)   # ← 앞에서
        if node in visited:
            continue
        visited.add(node)
        if node == goal:
            return visited
        frontier += neighbors(node)
 
def dfs(start, goal, neighbors):
    frontier = [start]
    visited = set()
    while frontier:
        node = frontier.pop()    # ← 뒤에서
        if node in visited:
            continue
        visited.add(node)
        if node == goal:
            return visited
        frontier += neighbors(node)

pop(0)은 큐, pop()은 스택입니다. 실제로는 collections.deque의 popleft()를 쓰면 훨씬 빠릅니다.
