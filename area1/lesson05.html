  • 이 동물은 고기를 먹고, 이빨이 날카롭습니다.

사진도 없고 이름도 알려 주지 않았습니다. 그런데 여러분은 벌써 “포유류이고, 육식 동물이겠구나”라고 생각했을 것입니다. 알려 준 적 없는 사실을 어떻게 알아냈을까요?

여러분 머릿속에 “젖을 먹이면 포유류다”라는 규칙이 이미 들어 있었기 때문입니다. 컴퓨터에게도 이런 규칙을 넣어 주면, 같은 일을 할 수 있을까요?

힌트 지난 차시와 무엇이 다를까?
지난 네 차시는 “어디로 가야 하나”를 찾는 탐색이었습니다. 이번 차시는 “이미 아는 것에서 무엇을 더 알아낼 수 있나”를 다루는 추론입니다. 인공지능의 두 축 가운데 나머지 하나이지요.
1

자료에서 지식까지

“추론에 쓰는 지식”을 이야기하기 전에, 비슷해 보이는 세 낱말을 구별해야 합니다. 관찰·측정·조사로 얻은 가공되지 않은 사실을 데이터라고 합니다. 이것을 가공하여 의미를 부여한 것이 정보이고, 정보를 일반화·체계화하여 여러 상황에 두루 쓸 수 있게 만든 것이 지식입니다.

인공지능이 추론을 하려면, 이 지식을 컴퓨터가 다룰 수 있는 형태로 바꾸어 저장해야 합니다. 이것을 지식 표현이라고 합니다.

2

지식을 기호로 적는 방법

명제 논리 — 참·거짓을 기호로

참 또는 거짓을 판별할 수 있는 문장을 명제라고 합니다. 명제 논리는 명제를 A, B 같은 기호로 바꾸고, 논리 연산자로 이어 붙여 지식을 표현합니다.

A: “비가 온다”, B: “습도가 높아진다”, C: “나는 우산을 가지고 있다”
논리 연산자기호 표현읽는 법
논리 부정 (NOT)NOT A비가 오지 않는다
논리곱 (AND)A AND B비가 오고, 습도가 높아진다
논리합 (OR)A OR C비가 오거나, 나는 우산을 가지고 있다
조건 또는 함축 (→)A → B비가 오면 습도가 높아진다

추론에서 가장 중요한 연산자는 →입니다. “A → B이고 A가 참이면 B도 참”이라는 규칙 하나로 새로운 사실을 만들어 낼 수 있기 때문입니다.

술어 논리 — 대상과 관계까지

명제 논리는 문장 하나를 기호 하나로 뭉뚱그리므로, “누가 어떻다”를 표현할 수 없습니다. 문장을 주어와 술부로 나누고 변수와 한정자를 도입해 대상과 관계를 표현하는 방법이 술어 논리입니다.

📘 술어 논리로 삼단논법 쓰기

∀x, 사람(x) → 죽는다(x)  — 모든 x에 대하여, x가 사람이면 x는 죽는다.
사람(소크라테스)  — 소크라테스는 사람이다.
∴ 죽는다(소크라테스)  — 그러므로 소크라테스는 죽는다.

∀는 “모든”(전칭 기호), ∃는 “어떤”(존재 기호)을 뜻합니다. 술어 논리를 프로그래밍 언어로 만든 것이 프롤로그(Prolog)입니다.

규칙과 사실 — 이 차시의 주인공

“~이면 …이다” 꼴로 조건과 결론을 서술하는 표현 방법을 규칙이라고 합니다. IF 조건 THEN 결론 형태라 사람이 읽고 이해하기 아주 쉽습니다. 조건이 여러 개면 AND, OR로 연결합니다.

규칙으로 표현한 지식
부분보기 1보기 2
IF (조건)신호등이 녹색불이다눈이 충혈되었다 AND 눈을 깜빡일 때 통증이 있다
THEN (결론)횡단보도를 건넌다결막염으로 진단한다

규칙과 짝을 이루는 것이 사실입니다. 규칙이 “일반적으로 이러하다”는 지식이라면, 사실은 “지금 이 경우는 이러하다”는 개별 정보입니다. 규칙 + 사실 → 새로운 사실이 이 차시의 핵심 공식입니다.

🔍 그 밖의 표현 방법

의미망은 개념을 점으로, 관계를 선으로 그려 “참새 —is a→ 새 —has→ 날개”처럼 나타냅니다. 프레임은 하나의 대상을 “속성: 값” 묶음으로 정리합니다. 지식 그래프는 이 아이디어를 거대한 규모로 확장한 것으로, 오늘날 검색 엔진이 “봉준호 감독의 영화”를 이해하는 데 쓰입니다.

규칙 기반 시스템 — 지식 베이스와 추론 엔진

규칙과 사실을 모아 두고, 거기서 새 사실을 만들어 내는 프로그램을 규칙 기반 시스템이라고 합니다. 특정 분야 전문가의 판단을 모방한 규칙 기반 시스템을 특히 전문가 시스템이라고 부릅니다. 전문가 시스템은 세 부분으로 이루어집니다.

그림 2. 전문가 시스템의 세 구성 요소

규칙과 사실이 저장되는 곳이 지식 베이스이고, 지식 베이스를 이용해 새로운 사실을 만들어 내는 부분이 추론 엔진입니다. 사람은 사용자 인터페이스를 통해 사실을 넣고 결론을 받습니다.

전방 추론과 후방 추론

추론 엔진이 일하는 방향은 두 가지입니다. 지금 가진 사실에서 출발해 발동할 수 있는 규칙을 찾아 새 사실을 계속 더해 가는 방식을 전방 추론이라고 합니다. 반대로 알고 싶은 결론에서 출발해 “이 결론을 내려면 어떤 조건이 필요한가”를 거꾸로 따라가는 방식을 후방 추론이라고 합니다.

두 추론 방향의 비교
구분전방 추론후방 추론
출발점지금 알고 있는 사실확인하고 싶은 결론(가설)
진행 방향사실 → 규칙 → 새 사실 → …결론 → 필요한 조건 → 그 조건의 조건 → …
알맞은 상황사실은 많고 무엇이 나올지 모를 때 (모니터링·진단)확인할 결론이 정해져 있을 때 (질의 응답)

삼단논법 — 추론의 가장 오래된 뼈대

대전제와 소전제에서 결론을 이끌어 내는 논증 형식을 삼단논법이라고 합니다. 규칙 기반 시스템의 한 단계가 바로 이 구조입니다.

✅

긍정 논법 — 타당

대전제 P → Q, 소전제 P ⇒ 결론 Q. “사람은 죽는다 + 소크라테스는 사람이다 ⇒ 소크라테스는 죽는다”

✅

부정 논법 — 타당

대전제 P → Q, 소전제 NOT Q ⇒ 결론 NOT P. “비가 오면 땅이 젖는다 + 땅이 젖지 않았다 ⇒ 비가 오지 않았다”

⛔

후건 긍정 — 부당

P → Q, Q ⇒ P는 틀립니다. 땅이 젖었다고 반드시 비가 온 것은 아닙니다. 물청소를 했을 수도 있습니다.

⛔

전건 부정 — 부당

P → Q, NOT P ⇒ NOT Q도 틀립니다. 비가 오지 않아도 다른 이유로 땅이 젖을 수 있습니다.

⚠️ 가장 많이 하는 실수

P → Q가 참이라고 해서 Q → P가 참인 것은 아닙니다. “열이 나면 감염이다”가 성립해도 “감염이면 열이 난다”는 별개의 주장입니다. 화살표의 방향을 뒤집는 순간 논증은 무너집니다. 시뮬레이터 2에서 직접 판정해 보세요.

심화 연역적 추론과 귀납적 추론

이 차시에서 다룬 규칙 기반 추론은 연역적 추론입니다. 일반적인 규칙에서 개별 사실을 이끌어 내며, 전제가 참이면 결론도 반드시 참입니다. 그래서 결론이 확실하지만, 새로운 규칙을 발견하지는 못합니다.

반대로 귀납적 추론은 여러 개별 사례에서 일반 규칙을 이끌어 냅니다. “관찰한 백조가 모두 흰색이었다 ⇒ 백조는 흰색이다”처럼요. 규칙을 새로 만들어 낼 수 있지만, 결론이 반드시 참이라는 보장은 없습니다(검은 백조가 나타날 수 있으니까요).

2단원의 기계학습은 본질적으로 귀납적 추론입니다. 데이터에서 규칙을 찾아내지만, 학습에 쓰지 않은 새 데이터에서 틀릴 수 있습니다. “왜 성능 평가가 반드시 필요한가”의 뿌리가 여기에 있습니다.

코드 파이썬 20줄로 만든 전방 추론 엔진

시뮬레이터 1이 실제로 하는 일을 파이썬으로 옮기면 이렇게 짧습니다.

rules = [
    (["젖을 먹인다"],                          "포유류"),
    (["포유류", "고기를 먹는다"],               "육식 동물"),
    (["육식 동물", "검은 줄무늬가 있다"],        "호랑이"),
]

def forward_chain(facts, rules):
    facts = set(facts)
    while True:
        fired = False
        for i, (conds, concl) in enumerate(rules):
            if concl in facts:
                continue                       # 이미 알고 있는 사실
            if all(c in facts for c in conds):  # 조건이 모두 만족되면
                facts.add(concl)                # 새 사실 도출
                print(f"규칙 {i+1} 발동 → {concl}")
                fired = True
                break
        if not fired:                           # 더 발동할 규칙이 없으면
            return facts                        # 추론 종료

print(forward_chain(["젖을 먹인다", "고기를 먹는다", "검은 줄무늬가 있다"], rules))

핵심은 while 안의 두 줄입니다. 조건이 모두 사실 집합에 들어 있으면 결론을 사실 집합에 넣는다 — 이것을 더 넣을 것이 없을 때까지 반복하면 전방 추론이 됩니다.

사례 MYCIN — 의사보다 잘 진단한 1970년대 인공지능

1972년 스탠퍼드 대학에서 만든 MYCIN은 혈액 감염병의 원인균을 찾아 항생제를 추천하는 전문가 시스템입니다. 약 600개의 규칙을 담았고, 후방 추론으로 “이 균이 원인이려면 어떤 검사 결과가 필요한가”를 거꾸로 물어 가며 환자에게 질문했습니다. 평가 실험에서 전문의보다 높은 정확도를 보인 것으로 알려져 있습니다.

그런데 MYCIN은 병원에서 널리 쓰이지 못했습니다. 규칙 600개를 계속 갱신할 사람이 필요했고, 새 항생제가 나올 때마다 지식 베이스를 손봐야 했기 때문입니다. “성능은 좋지만 유지할 수 없다”는 것이 규칙 기반 인공지능의 결정적 한계였습니다.

MYCIN은 규칙마다 확신도(0~1)를 붙여 불확실성을 다뤘습니다. 오늘날 기계학습 모델이 확률을 출력하는 것과 같은 문제 의식입니다.

연결 1단원 마무리 — 탐색과 추론, 그리고 그다음
1단원에서는 인공지능이 지능적으로 판단하는 두 가지 방식을 배웠습니다. 문제를 상태 공간으로 바꾸어 길을 찾는 탐색(2~4차시)과, 지식을 규칙으로 적어 새 사실을 만드는 추론(5차시)입니다. 두 방식의 공통점은 사람이 규칙과 평가 기준을 직접 설계한다는 점입니다. 2단원에서는 이 역할을 데이터에 넘기는 기계학습으로 넘어갑니다. 그전에 단원 마무리에서 배운 내용을 한 번에 정리해 보세요.
