🤔 생각 열기

지난 차시의 미로에서 두 사람은 출구가 어디인지 전혀 몰랐습니다. 그래서 목표와 아무 상관없는 방향까지 부지런히 뒤져야 했지요.

이번에는 조건이 하나 달라졌습니다. 미로 천장이 유리로 되어 있어서, 어느 칸에 서 있든 출구가 대략 어느 쪽에 있는지 보인다고 해 봅시다. 벽에 막혀 실제로 몇 걸음이 걸릴지는 모르지만, 직선거리는 눈으로 짐작할 수 있습니다.

  • 가온은 “출구에 가까워 보이는 칸부터” 무조건 먼저 가 봅니다.
  • 나리는 “여기까지 이미 걸어온 걸음 수”와 “출구까지 남았을 것 같은 걸음 수”를 더해서 가장 작은 칸부터 가 봅니다.

둘 중 누가 더 빨리 도착할까요? 그리고 누가 더 짧은 길로 도착할까요? 두 질문의 답은 서로 다릅니다.

힌트 가온의 방법에 어떤 함정이 있을까?
출구에 가까워 보이는 칸이 막다른 골목 입구일 수도 있습니다. 가온은 “지금까지 얼마나 멀리 돌아왔는지”를 전혀 계산하지 않기 때문에, 조금 가까워 보이는 쪽으로 계속 끌려가다가 크게 돌아가는 길을 답으로 내놓을 수 있습니다. 나리의 방법이 바로 이 차시의 주인공 A* 알고리즘입니다.
1

정보를 쓰면 탐색이 달라진다

지난 차시의 너비 우선 탐색과 깊이 우선 탐색은 목표가 어디 있는지에 대한 정보를 전혀 쓰지 않는 맹목적 탐색이었습니다. 그래서 상태 공간이 조금만 커져도 확인해야 할 상태 수가 폭발적으로 늘어납니다.

이미 알고 있는 경험이나 지식을 탐색에 활용하여 목표 상태를 찾는 방법을 정보 이용 탐색이라고 합니다. 여기서 쓰는 “경험적 지식”을 휴리스틱이라고 부릅니다.

📘 개념

휴리스틱은 문제를 해결할 때 쓰는 경험적 지식이다. 어떤 상태 n에서 목표 상태까지 남은 비용을 추정한 값을 그 상태의 휴리스틱값이라 하고, 이를 계산하는 함수를 휴리스틱 함수 h(n)이라고 한다.

휴리스틱값은 정확한 답이 아니라 추측입니다. 벽이 어디 있는지 모른 채 “직선거리로 12칸쯤 남았네”라고 어림하는 것이지요. 실제로는 벽을 돌아가야 하므로 15칸이 걸릴 수도 있습니다. 그래서 휴리스틱값은 사람마다 다르게 정의할 수 있고, 어떻게 정의하느냐가 탐색 성능을 좌우합니다.

좋은 휴리스틱의 조건

🎯

① 실제 비용을 넘지 않는다

추정값이 실제 남은 비용보다 크지 않아야 합니다. 즉 절대 과대평가하지 않아야 합니다. 이 조건을 지키면 A* 알고리즘이 최적 경로를 보장합니다.

📈

② 그러면서도 실제에 가깝다

항상 0을 내놓는 휴리스틱도 조건 ①은 지킵니다. 하지만 아무 정보도 주지 않으므로 쓸모가 없습니다. 실제 비용에 가까울수록 확인하는 상태 수가 줄어듭니다.

⚡

③ 계산이 빠르다

휴리스틱값은 상태마다 계산합니다. 한 번 계산하는 데 시간이 오래 걸리면, 탐색 횟수를 줄여서 얻은 이득이 사라집니다.

⚠️ 값이 클수록 좋은 걸까, 작을수록 좋은 걸까?

교과서마다 표기가 다릅니다. “목표와 일치하는 칸 수”처럼 클수록 좋은 평가 함수를 쓰는 경우도 있고, “남은 거리”처럼 작을수록 좋은 평가 함수를 쓰는 경우도 있습니다. 이 차시에서는 남은 비용을 추정하므로 값이 작을수록 목표에 가깝다고 봅니다. 중요한 것은 숫자의 방향이 아니라 “어떤 기준으로 다음 상태를 고르는가”입니다.

2

평가 함수 — 다음에 어느 칸을 열어 볼까

탐색은 결국 “후보 상태 중 어느 것을 먼저 확인할지”를 정하는 일입니다. 이 우선순위를 계산하는 함수를 평가 함수 f(n)이라고 합니다.

그림 1. 평가 함수의 두 부분 — 실선은 이미 걸어온 길(사실), 점선은 남았다고 짐작한 길(추정)

여기서 g(n)은 시작 상태에서 상태 n까지 실제로 지나온 비용이고, h(n)은 상태 n에서 목표까지 남았다고 추정한 비용입니다. 무엇을 평가 함수로 쓰는지에 따라 알고리즘의 이름이 달라집니다.

최상 우선 탐색 — 빠르지만 성급하다

최상 우선 탐색은 후보 중에서 h(n)이 가장 작은 상태를 고릅니다. 목표에 가까워 보이는 쪽으로만 달려가므로 확인하는 상태 수가 매우 적고 빠릅니다. 하지만 여기까지 얼마나 돌아왔는지를 아예 무시하기 때문에, 벽에 막혀 크게 우회한 길을 답으로 내놓을 수 있습니다. 그래서 최단 경로를 보장하지 않습니다.

A* 알고리즘 — 사실과 추정을 함께 본다

A* 알고리즘은 f(n) = g(n) + h(n)이 가장 작은 상태를 고릅니다. g(n)이 들어 있으므로 “많이 돌아온 길”에는 자동으로 벌점이 붙고, h(n)이 들어 있으므로 목표와 반대 방향은 잘 열어 보지 않습니다. 두 정보를 함께 쓰는 덕분에 빠르면서도 최적일 수 있습니다.

✅ A*가 최적 경로를 보장하는 조건

모든 상태에서 h(n) ≤ (실제 남은 최소 비용)이면, 즉 휴리스틱이 실제 비용을 과대평가하지 않으면 A*가 찾은 경로는 항상 최적 경로입니다. 반대로 h(n)을 실제보다 크게 잡으면 A*는 더 빨라지지만 최적을 놓칠 수 있습니다.

왜 그럴까요? f(n)은 “이 상태를 거쳐 가는 전체 비용의 낙관적 예상치”입니다. h가 과대평가하지 않으면 f는 실제 전체 비용보다 크지 않으므로, 진짜 최적 경로 위의 상태들은 다른 후보보다 f가 작게 유지되어 결국 먼저 열립니다.

🔍 h(n) = 0으로 두면?

휴리스틱을 무조건 0으로 두면 f(n) = g(n)이 되어, A*는 “가까운 것부터 차례로” 꺼내게 됩니다. 이동 비용이 모두 같은 격자에서는 이것이 너비 우선 탐색과 사실상 같습니다. 즉 A*는 맹목적 탐색을 특별한 경우로 포함하는 더 넓은 알고리즘입니다. 시뮬레이터에서 휴리스틱을 h = 0으로 바꿔 직접 확인해 보세요.

거리는 어떻게 재고, 후보는 어디에 담을까

맨해튼 거리와 유클리드 거리

격자에서 위·아래·왼쪽·오른쪽으로만 움직일 수 있다면, 두 칸 사이의 거리는 가로 차이와 세로 차이를 더한 값입니다. 이를 맨해튼 거리라고 합니다. 반면 자를 대고 직선으로 잰 거리는 유클리드 거리입니다.

그림 2. 같은 두 칸 사이의 거리 — 파란 선은 맨해튼 거리(11), 노란 점선은 유클리드 거리(약 8.06)

가로·세로로만 움직이는 격자에서는 맨해튼 거리가 유클리드 거리보다 실제 이동 횟수에 더 가깝습니다. 유클리드 거리는 대각선으로 날아가는 것을 가정하므로 언제나 맨해튼 거리보다 작거나 같고, 그만큼 더 느슨한 추정이 됩니다. 둘 다 실제 비용을 과대평가하지 않으므로 A*의 최적성은 지켜지지만, 맨해튼 쪽이 더 적은 칸을 확인합니다.

⚠️ 대각선 이동이 가능하다면?

대각선으로도 한 걸음에 갈 수 있는 격자에서는 맨해튼 거리가 실제 비용을 과대평가할 수 있습니다. 예를 들어 대각선 한 칸은 실제로 1걸음인데 맨해튼 거리는 2로 계산합니다. 이때는 최적성이 깨지므로 유클리드 거리나 다른 거리를 써야 합니다. 휴리스틱은 문제의 이동 규칙에 맞게 골라야 합니다.

열린 목록과 닫힌 목록

정보 이용 탐색은 후보를 두 개의 목록으로 관리합니다. 아직 확인하지 않은 후보 상태를 담는 곳이 열린 목록이고, 확인이 끝난 상태를 담는 곳이 닫힌 목록입니다.

  1. 시작 상태를 열린 목록에 넣는다.
  2. 열린 목록에서 평가 함숫값이 가장 작은 상태를 꺼낸다. (동점이면 h가 작은 쪽)
  3. 꺼낸 상태를 닫힌 목록에 넣는다. 그 상태가 목표면 종료하고 경로를 되짚어 만든다.
  4. 이웃 상태의 g를 계산해, 처음 보는 상태이거나 더 싸게 오는 길을 찾았으면 갱신하여 열린 목록에 넣는다.
  5. 열린 목록이 빌 때까지 2~4를 반복한다. 비었는데도 목표를 못 찾았다면 경로가 없다.

4단계에서 “더 싸게 오는 길을 찾았으면 갱신”하는 부분이 A*의 중요한 장치입니다. 최상 우선 탐색은 g를 보지 않으므로 이 갱신을 하지 않고, 처음 발견한 길을 그대로 씁니다. 바로 이 차이가 최적성의 유무를 만듭니다.

심화 8-퍼즐의 휴리스틱 — 어떤 것이 더 좋을까

3×3 판에 1~8이 흩어져 있는 8-퍼즐에서도 휴리스틱을 정의할 수 있습니다. 대표적으로 두 가지가 있습니다.

  • h₁ — 제자리에 없는 타일 수: 목표 위치와 일치하지 않는 타일의 개수(빈칸 제외). 계산이 아주 간단합니다.
  • h₂ — 타일별 맨해튼 거리의 합: 각 타일이 제 위치까지 가야 하는 칸 수를 모두 더합니다.

타일 하나를 옮기려면 최소 한 번은 움직여야 하므로 둘 다 실제 비용을 과대평가하지 않습니다. 그런데 언제나 h₂ ≥ h₁입니다. 제자리에 없는 타일은 맨해튼 거리가 최소 1이니까요. 더 큰 쪽이 실제 비용에 더 가까운 추정이므로, h₂를 쓰면 A*가 확인하는 상태 수가 크게 줄어듭니다.

이처럼 두 휴리스틱이 모두 과대평가하지 않을 때, 더 큰 값을 주는 휴리스틱이 더 좋은 휴리스틱입니다. 시뮬레이터에서 맨해튼(큰 값)과 유클리드(작은 값)를 번갈아 골라 보면 같은 원리를 확인할 수 있습니다.

코드 파이썬으로 쓴 A* — 3차시 코드에서 무엇이 바뀌었나

3차시의 탐색 뼈대에서 “꺼내는 기준”만 f = g + h로 바꾸면 A*가 됩니다.

import heapq

def astar(start, goal, neighbors, cost, h):
    open_list = [(h(start), 0, start)]   # (f, g, 상태) 우선순위 큐
    g = {start: 0}
    came = {}
    closed = set()

    while open_list:
        f, gn, node = heapq.heappop(open_list)   # f 가 가장 작은 것
        if node in closed:
            continue
        closed.add(node)
        if node == goal:
            break

        for nb in neighbors(node):
            ng = gn + cost(node, nb)             # 이웃까지의 새 g
            if nb not in g or ng < g[nb]:       # 더 싸게 오는 길이면 갱신
                g[nb] = ng
                came[nb] = node
                heapq.heappush(open_list, (ng + h(nb), ng, nb))
    return g, came

여기서 h를 lambda n: 0으로 주면 균일 비용 탐색이 되고, f 자리에 h(nb)만 넣으면 최상 우선 탐색이 됩니다. 세 알고리즘이 사실 한 가족이라는 뜻입니다.

사례 우리 주변의 A* — 내비게이션과 게임

지도 앱이 경로를 찾을 때, 전국의 모든 도로를 다 뒤지지는 않습니다. 목적지 방향의 도로부터 우선 살펴보는 정보 이용 탐색을 쓰기 때문입니다. 이때 휴리스틱으로는 목적지까지의 직선거리 ÷ 최고 제한 속도 같은 값을 씁니다. 실제 도로는 직선보다 길고 제한 속도보다 느리므로, 이 값은 실제 소요 시간을 과대평가하지 않습니다.

게임 속 캐릭터가 장애물을 피해 클릭한 지점으로 걸어가는 것도 대부분 A*입니다. 지형을 격자나 그래프로 나누고, 지형별로 이동 비용을 다르게 주면(늪 3, 길 1) 자연스럽게 “늪을 피해 길로 돌아가는” 행동이 나타납니다. 이것이 g(n)에 비용을 넣는다는 말의 실제 의미입니다.

연결 다음 차시로 — 탐색으로는 풀 수 없는 문제
지금까지는 “좋은 길을 찾는” 문제를 다뤘습니다. 그런데 “새의 특징을 가졌으니 이 동물은 새다”처럼, 알고 있는 사실에서 새로운 사실을 이끌어 내는 일은 길찾기가 아닙니다. 다음 차시에서는 지식을 규칙과 사실로 표현하고, 추론으로 새 지식을 만들어 내는 규칙 기반 시스템을 직접 돌려 봅니다.
