🤔 생각 열기

두 모둠이 같은 주제로 프로젝트를 시작했습니다.

  • 가온 모둠은 곧바로 코드를 짜기 시작했습니다. 이틀 뒤 “그런데 우리 데이터에 정답이 없는데?”라는 말이 나왔습니다.
  • 나리 모둠은 첫 시간에 계획서를 썼습니다. 무엇을 판단할지, 데이터를 어디서 몇 개 모을지, 무엇으로 성능을 평가할지 적었습니다.

2주 뒤, 가온 모둠은 데이터를 처음부터 다시 모으고 있었고 나리 모둠은 모델을 두 번째로 고치는 중이었습니다. 두 모둠의 차이는 능력이 아니라 순서였습니다.

힌트 가온 모둠이 놓친 것은 정확히 무엇일까?
가온 모둠은 “무엇을 판단할 것인가”와 “그 판단을 배우려면 어떤 자료가 필요한가”를 정하지 않은 채 도구부터 잡았습니다. 이 차시에서는 이런 낭비를 막는 다섯 단계의 문제 해결 절차를 배우고, 그 절차대로 계획서를 직접 완성합니다.
1

계획이 반인 이유

인공지능 프로젝트는 보통 학기의 절반을 쓰는 긴 활동입니다. 이런 활동에서 가장 큰 손실은 코드가 틀리는 것이 아니라 엉뚱한 것을 만들어 놓고 나서야 그것을 아는 것입니다. 사진 3,000장을 다 모은 뒤 “우리가 판단하려던 게 이게 아니었네”를 깨달으면 되돌릴 시간이 없습니다.

그래서 인공지능 분야에는 오랫동안 다듬어진 표준 절차가 있습니다. 이 절차의 첫 단계가 문제 정의인 이유도 같습니다. 무엇을 판단할지 정하지 않으면 데이터도, 알고리즘도, 평가 방법도 고를 수 없습니다.

📘 개념 — 인공지능 문제 해결 절차 5단계

문제 정의 → 문제 해결에 적합한 데이터 수집 및 전처리 → 기계학습 유형과 알고리즘 선정 → 기계학습을 통한 모델 생성 → 성능 평가 및 수정

이 다섯 단계는 순서대로 진행하지만 한 방향으로만 흐르지는 않는다. 뒤 단계에서 문제가 드러나면 앞 단계로 되돌아가 고치고 다시 내려온다.

계획서를 쓰는 목적은 “계획대로만 하기”가 아닙니다. 오히려 계획서는 어디로 되돌아가야 할지 알려 주는 지도입니다. 성능이 낮게 나왔을 때, 계획서에 데이터 수집 방법과 평가 기준이 적혀 있으면 무엇을 바꿔야 하는지 금방 찾을 수 있습니다. 계획서가 없으면 “그냥 다시 해 보자”밖에 남지 않습니다.

2

다섯 단계, 산출물과 함정

각 단계는 반드시 손에 잡히는 산출물을 남겨야 합니다. 산출물이 없는 단계는 “했다고 생각했지만 안 한 단계”입니다.

인공지능 문제 해결 절차 5단계 — 산출물과 흔한 실수
단계하는 일산출물흔한 실수
① 문제 정의 무엇을 입력하면 무엇을 내놓을지, 성공 기준은 무엇인지 정한다 주제 한 문장, 판단 문장, 성공 기준(예: 정확도 80%) “환경을 지킨다”처럼 판단이 없는 문장을 쓴다
② 데이터 수집 및 전처리 필요한 데이터를 모으고 결측치·이상치를 정리하고 속성을 가공한다 정리된 데이터 표(또는 폴더), 레이블, 전처리 기록 데이터 개수를 세어 보지 않고 “인터넷에서 찾는다”로 넘긴다
③ 기계학습 유형과 알고리즘 선정 지도·비지도·강화 중 유형을 정하고 그에 맞는 알고리즘을 고른다 선택한 유형·알고리즘과 고른 이유 유행하는 알고리즘을 먼저 정하고 문제를 억지로 맞춘다
④ 모델 생성 훈련 데이터로 학습시키고 하이퍼파라미터를 조정한다 학습된 모델, 학습 설정 기록 테스트 데이터까지 학습에 써 버려 성능이 부풀려진다
⑤ 성능 평가 및 수정 테스트 데이터로 지표를 계산하고, 원인을 찾아 앞 단계를 고친다 평가 지표 값, 개선 계획과 재실행 결과 숫자만 적고 “왜 낮은지”를 따지지 않는다

② 데이터 수집과 전처리

모은 데이터는 대부분 그대로 쓸 수 없습니다. 비어 있는 값인 결측치를 채우거나 지우고, 지나치게 튀는 값인 이상치를 확인하고, 단위가 다른 속성의 범위를 맞추는 정규화를 합니다. 이렇게 데이터를 학습에 쓸 수 있는 모양으로 다듬는 작업을 전처리라고 합니다.

2단원에서 배웠듯이, 이 단계에 쓰는 시간이 프로젝트 전체의 절반을 넘는 일이 흔합니다. “좋은 모델”보다 “좋은 데이터”가 성능을 더 크게 바꾸기 때문입니다.

③ 유형과 알고리즘 선정 — 결과의 형태가 결정한다

이 단계는 감으로 고르는 것이 아니라 규칙에 따라 정해집니다. 판단의 결과가 범주(가능/불가능, 개/고양이)이면 분류 문제이고, 결과가 수치(내일 잔반량 몇 kg)이면 회귀 문제입니다. 이 두 가지는 정답이 붙은 데이터로 배우므로 모두 지도학습에 속합니다.

반대로 정답 레이블이 없고 비슷한 것끼리 묶기만 한다면 군집 문제이므로 비지도학습을 골라야 합니다. 정답이 없는데 지도학습 알고리즘을 고르면 학습 자체가 시작되지 않습니다. 유형이 정해지면 알고리즘은 그 유형 안에서만 고르면 됩니다.

⚠️ 자주 나오는 잘못된 조합
  • 결과가 범주인데 선형 회귀를 고른다 → 선형 회귀는 수치를 내놓는 알고리즘입니다. 로지스틱 회귀·의사결정 트리·k-NN 같은 분류 알고리즘을 써야 합니다.
  • 레이블이 없다고 적어 놓고 지도학습을 고른다 → 레이블을 붙이는 작업을 2단계 계획에 넣거나 비지도학습으로 바꿔야 합니다.
  • 결과가 수치인데 k-평균 군집을 고른다 → 군집은 묶기만 하고 값을 예측하지 않습니다.

④ 모델 생성 — 데이터를 나누는 이유

모델을 학습시킬 때는 데이터를 훈련 데이터와 테스트 데이터로 나눕니다. 보통 훈련 70~80%, 테스트 20~30% 정도로 나눕니다. 테스트 데이터를 학습에 섞어 쓰면 시험 문제를 미리 보고 시험을 치는 것과 같아서, 성능이 실제보다 훨씬 좋게 나옵니다.

⑤ 성능 평가 및 수정 — 문제 유형에 맞는 지표를 쓴다

평가 지표는 문제 유형에 따라 다릅니다. 분류 문제는 혼동 행렬을 만들어 정확도·정밀도·재현율을 계산하고, 회귀 문제는 평균 절대 오차나 결정계수를 씁니다. 회귀 문제에 “정확도”를 쓰겠다고 적으면 계산 자체가 되지 않습니다. 지표를 정하는 것까지가 성능 평가 단계의 계획입니다.

3

절차는 한 방향이 아니다

다섯 단계를 계단처럼 한 번만 내려가는 프로젝트는 거의 없습니다. 5단계에서 성능이 낮게 나오면 그 원인에 따라 어느 단계로든 되돌아갑니다. 이렇게 앞 단계로 돌아가 고치고 다시 내려오는 성질을 절차의 반복적 성격이라고 합니다.

🔍 “성능은 높은데 쓸모가 없다”는 어떤 경우일까?

급식 잔반량을 예측하는 모델이 정확도 98%를 냈다고 해 봅시다. 그런데 확인해 보니 모델은 “거의 항상 평균값을 답한다”는 방식으로 맞히고 있었습니다. 조리실에서 필요한 것은 잔반이 많은 날을 미리 아는 것이었는데, 정작 그 날들을 전부 놓쳤습니다. 이럴 때는 지표를 바꾸거나 문제 정의로 되돌아가야 합니다.

심화 성공 기준을 숫자로 정하는 요령

“정확도 90% 이상”처럼 목표 수치를 정할 때는 기준선(baseline)과 비교해야 의미가 생깁니다. 기준선은 “아무 것도 학습하지 않은 가장 단순한 방법”의 성능입니다.

  • 분류에서 가장 많은 범주로만 답하는 방법의 정확도가 이미 85%라면, 90%는 별로 좋은 목표가 아닙니다.
  • 회귀에서는 항상 평균값으로 답하는 방법의 오차를 먼저 계산해 보고, 그보다 얼마나 줄일지를 목표로 삼습니다.

또한 문제에 따라 어떤 실수가 더 위험한지를 정해야 합니다. 재활용 가능한 것을 불가능으로 잘못 판단하는 것과, 불가능한 것을 가능으로 잘못 판단하는 것 중 무엇이 더 나쁜지에 따라 정밀도와 재현율 중 무엇을 더 중시할지가 달라집니다.

코드 다섯 단계를 파이썬 골격으로 옮기면

계획서의 다섯 단계는 실제 코드에서도 그대로 다섯 덩어리가 됩니다. 주석만 먼저 써 두고 아래에서 위로 채워 가면 길을 잃지 않습니다.

# ① 문제 정의 — 코드가 아니라 주석으로 남긴다
#   입력: 쓰레기 사진 1장  →  출력: 재활용 가능 / 불가능
#   성공 기준: 테스트 정확도 0.85 이상

# ② 데이터 수집 및 전처리
data = load_images('photos/')          # 300장
data = drop_missing(data)              # 결측치 제거
data = normalize(data)                 # 정규화
labels = load_labels('labels.csv')     # 정답 레이블

# ③ 기계학습 유형과 알고리즘 선정
#   결과가 범주 → 분류 → 지도학습
model = DecisionTreeClassifier(max_depth=6)

# ④ 모델 생성
x_train, x_test, y_train, y_test = split(data, labels, test_size=0.2)
model.fit(x_train, y_train)            # 훈련 데이터만 사용

# ⑤ 성능 평가 및 수정
pred = model.predict(x_test)           # 테스트 데이터로 평가
print(confusion_matrix(y_test, pred))  # 혼동 행렬
print(accuracy(y_test, pred), recall(y_test, pred))
#   → 성능이 낮으면 ②·③·④ 중 어디로 되돌아갈지 판단한다

model.fit에 x_test를 넣지 않는 것이 4단계의 핵심 규칙입니다. 이 한 줄을 어기면 평가 결과 전체가 의미를 잃습니다.
