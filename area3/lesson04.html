🤔 생각 열기

어떤 회사가 채용 서류를 자동으로 심사하는 인공지능을 만들었습니다. 개발자는 공정하게 만들려고 아주 신경을 썼습니다.

  • 지원서에서 이름·성별·나이·출신 지역을 모두 지웠습니다.
  • 차별하라는 규칙은 한 줄도 넣지 않았습니다.
  • 모델은 지난 10년간의 합격·불합격 기록으로 학습했습니다.

1년 뒤 결과를 집계해 보니, 특정 지역 출신 지원자의 합격률이 다른 지역의 절반도 되지 않았습니다. 개발자는 억울해합니다. “저는 그런 규칙을 넣지 않았는데요.”

무엇이 잘못되었을까요? 그리고 이 회사는 무엇을 고쳐야 할까요?

힌트 세 번째 항목을 다시 읽어 보기
모델은 “합격시켜야 할 사람”을 배우지 않았습니다. “과거에 합격했던 사람”을 배웠습니다. 두 문장은 완전히 다릅니다. 이 차시의 첫 번째 시뮬레이터에서 이 차이가 만드는 격차를 직접 계산해 확인합니다.
1

왜 인공지능에 윤리가 필요한가

망치에는 윤리가 필요하지 않습니다. 망치는 스스로 무엇도 결정하지 않기 때문입니다. 그런데 인공지능은 사람에 관한 결정을 대신 내리거나 결정에 영향을 줍니다. 누가 대출을 받고, 누가 면접에 오고, 어떤 게시물이 사람들에게 보이는지가 모델의 출력에 달려 있습니다. 결정에 관여하는 것은 규모와 속도까지 갖춘 결정입니다.

인공지능 윤리는 개발자의 착한 마음가짐을 뜻하는 말이 아닙니다. 인공지능을 만들고 쓰고 운영하는 과정에서 누가 무엇을 확인하고 무엇을 기록하고 누가 책임지는지를 정하는 실무 규칙에 가깝습니다.

📘 우리나라의 기준

우리나라는 2020년에 사람 중심 인공지능 구현을 위한 국가 인공지능 윤리기준을 마련했습니다.

  • 3대 기본 원칙 — 인간 존엄성 원칙, 사회의 공공선 원칙, 기술의 합목적성 원칙
  • 10대 핵심 요건 — 인권 보장, 프라이버시 보호, 다양성 존중, 침해 금지, 공공성, 연대성, 데이터 관리, 책임성, 안전성, 투명성
⚠️ 오해 주의

“나쁜 의도가 없으면 윤리 문제도 없다”는 생각이 가장 흔한 오해입니다. 이 차시에서 다룰 문제 대부분은 아무도 나쁜 의도를 갖지 않은 상태에서 발생합니다. 편향은 데이터에 성실했기 때문에 생기고, 설명 불가능성은 성능을 높이려 했기 때문에 생깁니다. 그래서 의도를 따지는 것만으로는 부족하고, 결과를 측정하는 절차가 필요합니다.

2

편향은 어디서 들어오는가 — 세 개의 문

“인공지능이 편향되었다”는 말은 너무 뭉뚱그린 표현입니다. 편향은 서로 다른 세 개의 문을 통해 들어오고, 문마다 막는 방법이 다릅니다.

① 데이터 — 대표성 부족과 과거 차별의 기록

모델을 만드는 데 쓰인 데이터에 들어 있는 편향을 데이터 편향이라고 합니다. 데이터 편향은 다시 두 갈래로 나뉩니다.

  • 대표성이 부족한 경우 — 어떤 집단의 데이터가 지나치게 적으면 모델은 그 집단에서 잘 작동하지 않습니다. 사투리 음성이 적으면 사투리를 못 알아듣습니다. 모델이 차별하려 한 것이 아니라 배울 기회가 없었을 뿐입니다.
  • 과거 차별이 기록으로 남은 경우 — 이쪽이 훨씬 까다롭습니다. 데이터의 양이 충분하고 잡음도 없는데, 정답 표시(레이블) 자체가 과거의 불공정한 결정일 때가 있습니다. 과거 합격 기록으로 학습한 채용 모델이 바로 이 경우입니다. 모델은 데이터에 충실할수록 과거의 차별을 정확하게 재현합니다.

② 알고리즘 — 무엇을 최적화하도록 설계했는가

기계학습 알고리즘 자체의 설계나 구현에 내재된 편향을 알고리즘 편향이라고 합니다. 핵심 질문은 하나입니다. 모델에게 무엇을 잘하라고 시켰는가?

추천 알고리즘에게 “머문 시간을 늘려라”라고 시키면, 알고리즘은 사람을 오래 붙잡는 방법을 찾아냅니다. 그것이 자극적인 내용이라면 그쪽으로 갑니다. 이것은 알고리즘의 실패가 아니라 주어진 목표를 정확히 달성한 결과입니다. 전체 정확도만 목표로 삼는 경우도 마찬가지입니다. 데이터의 90%를 차지하는 집단에서 잘 맞히면 정확도는 높아지므로, 모델은 소수 집단을 포기하는 것이 이득이라고 학습합니다.

③ 사람 — 개발자의 가정과 해석

세 번째 문은 사람입니다. 어떤 속성을 입력에 넣을지, 무엇을 ‘좋은 성과’로 볼지, 결과를 어떻게 해석할지는 모두 사람이 정합니다. “근무 연수가 길면 우수한 직원”이라는 가정 하나가 육아휴직을 쓴 사람에게 불리하게 작동할 수 있습니다. 데이터에도 알고리즘에도 잘못이 없는데 결과가 치우치는 경우입니다.

🔍 편향은 돌고 돈다

세 경로는 한 방향이 아니라 고리를 이룹니다. 사회와 사람의 편향이 데이터에 기록되고, 데이터가 모델의 편향을 만들고, 모델이 내린 결정이 다시 새로운 데이터가 되어 편향을 강화합니다. 특정 지역 출신을 덜 뽑은 모델은 그 지역의 합격자 데이터를 더 줄여, 다음 모델이 같은 판단을 더 자신 있게 하도록 만듭니다. 이 고리를 끊으려면 결과를 주기적으로 측정해 되먹임을 확인하는 일이 필수입니다.

집단 정보만 빼면 되지 않을까 — 대리 변수

가장 자연스러운 해결책은 “민감한 정보를 입력에서 빼자”입니다. 그런데 이 방법은 대개 실패합니다. 지운 정보와 강하게 상관된 다른 속성이 남아 있으면, 모델은 그 속성을 통해 지운 정보를 되살려 냅니다. 이렇게 민감한 속성 대신 쓰이게 되는 속성을 대리 변수라고 합니다.

거주지 우편번호는 지역을, 졸업 학교는 출신지와 소득 수준을, 지원 시각은 직업 상태를 어느 정도 알려 줍니다. 그래서 집단 정보를 지웠다는 사실은 공정성의 증거가 되지 못합니다. 공정성은 입력에서 무엇을 뺐는지로 판단할 수 없고, 결과를 집단별로 측정해야만 확인할 수 있습니다. 첫 번째 시뮬레이터에서 이 현상을 직접 확인합니다.

3

공정성을 재는 세 가지 자, 그리고 나쁜 소식

공정성은 개인의 독특함을 나타내는 차이를 존중하고 누구도 배제하지 않는 원칙입니다. 문제는 이 원칙을 숫자로 옮기는 방법이 여러 가지라는 점입니다. 대표적인 세 가지를 봅시다.

공정성을 숫자로 옮기는 세 가지 방식
기준무엇이 같아야 하는가이 기준을 지지하는 이유
결과의 균등집단별 합격률이 같아야 한다결과의 격차 자체가 차별의 증거라고 본다
기회의 균등집단별 재현율이 같아야 한다
실제 자격자 중 합격한 비율		자격이 있는 사람은 어느 집단이든 같은 확률로 뽑혀야 한다
예측의 균등집단별 정밀도가 같아야 한다
합격 판정자 중 실제 자격자 비율		같은 점수를 받았다면 같은 의미여야 한다

세 기준은 모두 그럴듯합니다. 그런데 나쁜 소식이 있습니다. 두 집단에서 실제 자격자의 비율(기저율)이 다르면, 완벽한 예측이 아닌 한 이 기준들을 동시에 만족시킬 수 없습니다. 이것은 의견 차이가 아니라 수학적으로 증명된 사실입니다.

🔢 숫자로 확인해 보기

가람 집단 100명 중 자격자가 50명, 나루 집단 100명 중 자격자가 20명이라고 합시다(기저율이 다른 상황).

  • 합격률을 똑같이 30%로 맞추면, 가람에서는 자격자 50명 중 30명 이하만 뽑히고, 나루에서는 자격자 20명을 다 뽑고도 자리가 남아 비자격자가 들어옵니다. → 재현율과 정밀도가 집단별로 어긋납니다.
  • 재현율을 똑같이 맞추면 합격률이 달라집니다. 자격자가 많은 집단에서 더 많이 뽑히기 때문입니다.

즉 어느 자를 쓸지 고르는 순간 다른 자는 포기하게 됩니다. 그러므로 “이 모델은 공정한가?”라는 질문은 성립하지 않습니다. 물어야 할 것은 “어떤 공정성을 택했고, 왜 그것을 택했는가?”입니다. 이것은 계산이 아니라 사회가 논의해 정할 가치 판단입니다.

⚠️ 기저율 차이를 ‘자연스러운 것’으로 받아들이지 않기

기저율이 다르다는 사실 자체가 이미 과거 구조의 결과일 수 있습니다. 어떤 지역에 실습 기회나 교육 자원이 적었다면, 그 지역의 ‘자격자 비율’이 낮게 측정되는 것은 능력의 차이가 아니라 기회의 차이입니다. 기저율을 고정된 사실로 두고 계산만 하면, 과거의 불평등을 공정성의 전제로 삼는 셈이 됩니다.

4

투명성, 책임, 그리고 나의 데이터

투명성과 설명 가능성

인공지능이 사용하는 알고리즘과 수집한 데이터를 공개하여 판단 과정을 확인할 수 있게 하는 원칙을 투명성이라고 합니다. 그리고 인공지능의 판단 이유를 사람이 이해할 수 있는 방식으로 제시하는 인공지능을 설명 가능한 인공지능이라고 합니다.

둘은 같지 않습니다. 소스 코드를 전부 공개해도(투명성) 신경망의 판단 근거는 여전히 알 수 없고, 반대로 코드를 공개하지 않고도 “어떤 항목이 결과를 어느 쪽으로 얼마나 밀었는지”는 알려 줄 수 있습니다(설명 가능성). 당사자에게 필요한 것은 대개 후자입니다. 탈락한 지원자에게 필요한 정보는 코드가 아니라 “무엇이 결정적이었고 무엇을 바꾸면 결과가 달라지는가”입니다.

누가 책임지는가

인공지능의 개발 과정과 결과에 대한 책임을 분명히 하는 원칙을 책임성이라고 합니다. 인공지능이 관여한 사고에서 가장 흔한 실패는 “아무도 책임지지 않는 상태”입니다. 개발사는 “정해진 대로 만들었다”, 병원은 “인증된 제품을 썼다”, 의료진은 “시스템 권고를 따랐다”라고 말할 수 있기 때문입니다. 이런 상태를 책임의 공백이라고 부릅니다.

책임의 공백을 막는 방법은 사고가 난 뒤에 따지는 것이 아니라, 도입 전에 미리 분담을 문서로 정해 두는 것입니다. 어떤 조건에서 사람이 반드시 확인하는지, 판단 기록을 얼마나 남기는지, 이의 제기는 누가 처리하는지를 정해 두어야 합니다.

프라이버시와 데이터 주권

사생활을 보호하고 개인 정보의 오용을 최소화하는 원칙을 프라이버시 보호라고 합니다. 인공지능 시대에 이 원칙이 특히 어려워진 까닭은, 하나하나는 민감하지 않은 정보들을 모으면 민감해진다는 점입니다. 걸음 수, 위치, 검색어, 취침 시각은 따로 보면 대수롭지 않지만, 합치면 건강 상태와 생활 습관이 드러납니다.

그래서 최근에는 “정보를 지켜 준다”를 넘어, 내 데이터가 어디에 쓰이는지 알고 옮기고 삭제를 요구할 수 있어야 한다는 데이터 주권 개념이 강조됩니다. 동의 버튼을 한 번 눌렀다는 사실이 모든 용도에 대한 영구 허락이 될 수는 없다는 문제 제기입니다.

윤리적 딜레마의 구조

윤리적 딜레마란 도덕적으로 어떤 결정을 해야 할 때 여러 가치가 서로 충돌하여 쉽게 결정할 수 없는 난처한 상황을 말합니다. 딜레마를 잘 다루려면 그 구조를 볼 수 있어야 합니다.

📘 딜레마를 분해하는 네 가지 질문
  1. 충돌하는 가치가 무엇인가 — 안전과 자유? 효율과 배려? 개인의 권리와 공공의 이익?
  2. 누가 이득을 얻고 누가 부담을 지는가 — 이득과 부담을 지는 사람이 다르면 특히 신중해야 합니다.
  3. 되돌릴 수 있는가 — 되돌릴 수 없는 선택은 더 높은 확신을 요구합니다.
  4. 결정하지 않는 것도 결정이다 — 미루는 동안에도 현재 상태가 계속 작동합니다.
✅ 딜레마에는 정답이 없다, 그러나

심화 왜 여러 공정성 기준을 동시에 만족할 수 없는가

혼동 행렬을 떠올려 봅시다. 어떤 집단에서 실제 자격자 비율(기저율)을 p, 재현율을 TPR, 위양성률을 FPR이라고 하면, 정밀도는 다음과 같이 정해집니다.

정밀도 = p·TPR / ( p·TPR + (1−p)·FPR )

이 식에서 p가 집단마다 다르면, TPR과 FPR을 두 집단에서 똑같이 맞추더라도 정밀도는 자동으로 달라집니다. 반대로 정밀도를 맞추려면 TPR이나 FPR을 집단마다 다르게 두어야 합니다. 완전히 정확한 예측(TPR=1, FPR=0)일 때만 모든 기준이 함께 성립합니다.

이 결과의 의미는 “공정성은 불가능하다”가 아닙니다. “공정성이라는 말을 정의하지 않고 쓰면 논쟁이 끝나지 않는다”는 뜻입니다. 그래서 실무에서는 어떤 기준을 택했는지 명시하고, 나머지 기준의 값도 함께 공개하는 방식을 씁니다.

실무 편향을 실제로 줄이는 네 가지 지점

편향 완화는 한 방에 끝나는 일이 아니라, 파이프라인의 여러 지점에서 조금씩 하는 일입니다.

  • 데이터 단계 — 부족한 집단의 데이터를 더 모으거나, 표본에 가중치를 주어 균형을 맞춥니다. 레이블 자체가 의심스러우면 레이블 기준을 다시 정의합니다(“과거 합격” 대신 “입사 후 실제 성과”처럼).
  • 학습 단계 — 손실 함수에 집단 간 격차를 벌하는 항을 더해, 정확도와 공정성을 함께 최적화합니다.
  • 출력 단계 — 집단마다 판정 임계값을 다르게 두어 재현율을 맞추는 방법이 있습니다. 효과는 즉각적이지만, “집단에 따라 기준을 달리 적용해도 되는가”라는 새로운 논쟁을 부릅니다.
  • 운영 단계 — 가장 중요합니다. 집단별 지표를 정기적으로 측정해 공개하고, 격차가 기준을 넘으면 자동으로 재검토가 시작되도록 절차를 만듭니다. 측정하지 않으면 편향은 반드시 다시 자랍니다.
코드 집단별 지표를 계산하는 파이썬 코드

공정성 점검의 출발점은 언제나 “집단별로 나누어 세기”입니다. 아래 함수가 시뮬레이터가 실제로 하는 계산과 같습니다.

def group_report(y_true, y_pred, group):
    """집단별 합격률·정확도·재현율·정밀도를 계산한다."""
    for g in sorted(set(group)):
        idx = [i for i in range(len(group)) if group[i] == g]
        n   = len(idx)
        tp  = sum(1 for i in idx if y_pred[i] == 1 and y_true[i] == 1)
        fp  = sum(1 for i in idx if y_pred[i] == 1 and y_true[i] == 0)
        pos = sum(1 for i in idx if y_true[i] == 1)      # 실제 자격자
        acc = sum(1 for i in idx if y_pred[i] == y_true[i]) / n

        print(g,
              '합격률 %.3f' % ((tp + fp) / n),
              '정확도 %.3f' % acc,
              '재현율 %.3f' % (tp / pos if pos else 0),
              '정밀도 %.3f' % (tp / (tp + fp) if tp + fp else 0))

전체 정확도 하나만 보고하는 보고서는 공정성에 대해 아무것도 말해 주지 않습니다. 소수 집단이 전체의 10%라면, 그 집단을 모두 틀려도 전체 정확도는 10%만 떨어집니다.
